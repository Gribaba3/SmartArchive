# Формат архіву SARC v1 (відновлено з еталонних архівів викладача)

> Оригінального FORMAT_SPEC_P2.md у матеріалах немає. Цей опис отримано розбором
> `reference/ref_*.arc` з паролем із `team_config.json`. **Перевірено**: усі 6 еталонних
> наборів (8 томів, 25 файлів) розпаковуються, розміри й CRC32 збігаються, томи
> читаються в довільному порядку. Пункти, позначені ⚠, — припущення, не підтверджені даними.
> Межі формату (вікно, алфавіти, довжина коду, `E_CODE`, порожній архів) звірено з методичкою, розділ 10.

Усі цілі числа — **big-endian**, беззнакові.

## 1. Том = заголовок (41) + шифротекст + HMAC (32)

| Зміщення | Розмір | Поле | Приклад |
|---|---|---|---|
| 0 | 4 | magic `"SARC"` | `53 41 52 43` |
| 4 | 1 | версія = 1 | `01` |
| 5 | 2 | номер тому (з 0) | `00 00` |
| 7 | 2 | кількість томів | `00 01` |
| 9 | 16 | salt KDF (однаковий для всіх томів архіву) | |
| 25 | 12 | nonce (різний для кожного тому) | |
| 37 | 4 | ciphertext_len | |
| 41 | ciphertext_len | шифротекст payload | |
| 41+len | 32 | HMAC-SHA256 | |

- Розмір файлу тому **рівно** `41 + ciphertext_len + 32`.
- У еталонах nonce = `01 02 03 04 05 06 07 08` ‖ uint32(номер тому), salt = `00 01 … 0f`.
  Це для детермінованості; у своїх архівах salt і nonce — випадкові (`os.urandom`).

## 2. Криптографія

```
key   = PBKDF2-HMAC-SHA256(password_utf8, salt, 100000, dklen=64)
K_enc = key[0:32]      K_mac = key[32:64]
CTR   = AES-256-CTR, початковий лічильник = nonce(12) || uint32_BE(1)
tag   = HMAC-SHA256(K_mac, байти тому [0 : 41+ciphertext_len])   # заголовок + шифротекст
```
HMAC береться над **заголовком і шифротекстом** (перевірено; над самим шифротекстом не збігається).

## 3. Payload (після розшифрування)

```
u16  file_count
u16  reserved            = 0, інакше E_PAYLOAD
file_count × {
    u16  name_len
    name (UTF-8, name_len байтів, без шляху)
    u32  file_size        (повний розмір файлу, не частини в томі)
    u32  crc32            (усього файлу, zlib.crc32)
    u8   type             (клас 0–6 з team_config)
    u8   strategy         (в еталонах завжди 1) ⚠ значення не визначене
}
u16  block_count
block_count × {           # 15 байтів
    u16  file_index       (індекс у таблиці файлів ЦЬОГО тому)
    u32  block_index      (порядковий номер блоку всередині файлу, з 0)
    u32  raw_len
    u32  coded_len
    u8   method           0 = LZ77+Гаффман, 1 = без стиснення (STORED)
}
дані блоків підряд, у порядку таблиці блоків (coded_len байтів кожен)
```

- Службова частина payload = 4 + таблиця файлів + 2 + 15·блоків — звідси «6» у формулі W з config.
- Таблиця файлів тому містить **усі файли-кандидати**, навіть ті, з яких у цей том не потрапив жоден блок
  (у `ref_06.part0` файл f0012.z є в таблиці, хоча його блок 0 лежить у part1).
- Файл ділиться на блоки по `block_size` = 16384 байтів; останній — залишок. Порожній файл = 1 блок, raw_len = 0, method 1.
- Блоки одного файлу можуть лежати в різних томах і в довільному порядку; збирати за `block_index`.
- Кожен блок стискається **незалежно** (LZ77-посилання не виходять за межі блоку).

## 4. Блок method = 0 (LZ77 + канонічний Гаффман)

```
tree LIT      # алфавіт 0–256: 0–255 літерал, 256 = «далі посилання»
tree LEN      # символ = довжина_збігу − 3   (0–255 → довжина 3–258)
tree DIST     # символ b = bit_length(dist − 1)  (0–15)
u32  token_count     # літерали + посилання
u32  bitstream_len   # у байтах
bitstream
```
Кожне дерево: `u16 n`, далі n × (`u16 symbol`, `u8 code_length`). Записуються лише символи з довжиною > 0.
Порожнє дерево: n = 0.

**Канонічні коди:** сортувати пари за (довжина, символ); `code = 0`; для кожного наступного
`code = (code + 1) << (len − prev_len)` (перший: `code = 0 << len`). Один символ у дереві → довжина 1, код `0`.

**Бітовий потік:** біти пишуться **від старшого до молодшого** (MSB-first) у кожному байті,
останній байт доповнюється нулями. Для кожного токена:
```
літерал:   код LIT[byte]
посилання: код LIT[256], код LEN[len−3], код DIST[b], далі (b−1) додаткових бітів (якщо b ≥ 2)
           dist − 1 = (1 << (b−1)) | extra      ; b = 0 → dist = 1 ; b = 1 → dist = 2
```
Звідси фіксована вартість у config: літерал ≈ 9 біт, посилання 17 + max(0, bit_length(dist−1) − 1).

**Межі (методичка, 10.19–10.26):**
- MIN_MATCH = 3, MAX_MATCH = 258, вікно WINDOW = 32768 → dist 1…32768, символ DIST 0…15
  (32768 ще кодується символом 15, 32769 дав би 16 — недопустимо);
- алфавіти: LIT 0…256, LEN 0…255, DIST 0…15; символ поза алфавітом → `E_CODE`;
- довжина коду 1…15 біт; для одного символу — рівно 1; для більш ніж одного — **рівність** Крафта
  Σ 2^−L = 1 (неповний код теж відхиляється). Порушення → `E_CODE`.

У еталонах спостерігалося: dist ≤ 16384 (бо блок 16384), найдовший код 12 біт.

## 5. Коди відмов (з `expected_failures.json`)

Рекомендований порядок перевірок розархіватора:

| Порядок | Перевірка | Код |
|---|---|---|
| 1 | magic ≠ "SARC" або версія ≠ 1 | `E_MAGIC` |
| 2 | розмір файлу ≠ 41 + ciphertext_len + 32 | `E_LENGTH` |
| 3 | HMAC не збігається (сюди ж невірний пароль) | `E_HMAC` |
| 4 | reserved ≠ 0, вихід за межі payload, погане ім'я (`/ \ : NUL`, `..`, абсолютний шлях), file_index поза таблицею | `E_PAYLOAD` |
| 5 | некоректна таблиця кодів (довжини, Крафт, символ поза алфавітом), невідомий код, посилання за межі декодованого | `E_CODE` |
| 6 | CRC32 зібраного файлу не збігається | `E_CRC` |

Відсутній / дубльований том (номер повторюється, не всі 0…count−1, різні salt) — ⚠ код не заданий викладачем; ми використовуємо `E_VOLUME`.

Повтор nonce у різних томах одного архіву (ключ спільний, тому в CTR це однаковий гамма-потік) — теж `E_VOLUME`: такий архів небезпечний і не приймається.

Додатково відхиляються як `E_PAYLOAD`: однакові імена в таблиці тому; імена, що відрізняються лише регістром; імена, які не можна створити на Windows (`CON`, `NUL`, `COM1`…, `LPT1`…, кінцева крапка чи пробіл, керівні символи), довші за 255 байтів; `token_count > raw_len`, обрізаний блок чи бітовий потік. Символ, записаний у дереві двічі, — `E_CODE`.

Порожній архів (методичка, 10.39): 1 том, file_count = 0, block_count = 0.

| Файл | Що зіпсовано | Очікується |
|---|---|---|
| bad_01 | байт шифротексту (зміщення 48) | E_HMAC |
| bad_02 | останній байт тегу | E_HMAC |
| bad_03 | обрізано 11 байтів | E_LENGTH |
| bad_04 | байт magic | E_MAGIC |
| bad_05 | reserved = 1, HMAC перераховано (валідний) | E_PAYLOAD |
| bad_06 | поле CRC32 першого файлу, HMAC валідний | E_CRC |
